# 다음 작업 전달안 — 2026-09-14

전달용 초안. 팀원에게 실제 발송하지 않았다.
기준 기획은 [5원소 개편 기획](ElementSkillEliteBossPlan.md), 화면은 [성장 목업](Mockups/ElementSkillReview/index.html)이다.
과거 문서의 28노드·융합 작업을 이번 할 일로 가져오지 않는다.

## 선동 — 성장 규칙·소환·통합

1. 목업의 **원소 선택 → 해당 원소 특화 카드 3개 → 확정**을 실제 성장 규칙으로 연결한다. 현재 게임의 ‘원소 후보 최대 3개 추첨’과 다른 부분이다.
2. 특화 수치·누적 방식·미해금 효과의 예약 적용을 먼저 확정한다. 목업의 +10%, +2%p는 아직 제안값이다.
3. 확정 시 원소 레벨 +1, 특화 적용, 대기 횟수 -1을 한 번만 처리한다. 새 원소는 해금 카드 1개, 시작 무료 원소는 횟수 소모 없음. 정보 열람·중복 클릭·다중 레벨업·MAX 처리도 맡는다.
4. 승범에게 조회·선택·확정 API, 유신에게 원소·레벨·특화 수치 전달 계약을 제공한다. UI와 Combat에서 성장 상태를 따로 만들지 않게 한다.
5. 3분·6분 엘리트와 8분 보스의 **소환 시점·중복 방지·씬 연결은 선동 담당**. 유신의 최종 데이터를 받아 현재 임시 슬롯을 교체한다.
6. 전용 통합본과 새 마법 외형 20개·돌바닥을 유지하며 담당 결과를 병합·빌드한다. 이번 7→8 설명 오류 수정도 보존한다.

완료: 목업의 선택 규칙이 실제 성장에 반영되고, 확정/재시작에서 레벨·특화·포인트가 틀어지지 않는다.

## 유신 — 실제 마법 효과·엘리트·보스

1. 5원소의 3·5·7·8레벨 고유 전투 효과를 최신 기획에 맞춰 구현한다. 화염 점화·전염·장판, 번개 연쇄·방전·낙뢰, 냉기 빙결·파괴·서리, 대지 충격파·지진·낙석, 암흑 취약·전염·처형이다.
2. 기존 투사체·표식·EnemyManager를 재사용한다. 선동이 제공한 레벨·특화 값을 Combat에 적용하고, 실제 발동 위치·범위·대상 정보를 연출 연결에 제공한다.
3. 돌진자·소환술사·원소 수호자의 데이터·프리팹·행동을 만든다. 등장 시간과 씬 소환기를 새로 만들지 않는다.
4. 보스의 빙결·둔화·밀치기·처형 예외, 중복 발동 방지, 표식 만료와 풀 반환 초기화를 검증한다.

완료: 외형만 바뀌는 것이 아니라 실제 적에게 기획된 효과가 발생한다. 소환 가능한 EnemyData/프리팹과 자체 검증 결과를 전달한다.

## 승범 — 목업 기반 성장 UI·게임 UI

1. `Docs/Mockups/ElementSkillReview/index.html`의 **성장 화면**을 Unity UI로 옮긴다. 왼쪽 5원소 오각형, 오른쪽 선택 원소의 특화 카드 3개와 기본 성장 설명을 구현한다.
2. 새 원소는 해금 카드 1개. 미인접·MAX 원소는 선택 불가. 남은 선택 횟수, 선택 강조, 현재/다음 레벨을 표시한다.
3. 평소에는 성장 정보를 열람하고 대기 레벨업이 없으면 확정을 막는다. 선동의 공개 API를 사용하며 UI에서 레벨·특화·포인트를 직접 계산하지 않는다.
4. 기존 타이틀·HUD·결과 UI를 연결한다. 타이틀 제목·시작·설정·종료, 설정창 초기 숨김/열기/닫기, 결과 재시작/타이틀을 확인한다.
5. 1280×720·1920×1080에서 한글·버튼 가림·화면 잘림을 확인한다. 새 마법 성장 외형은 이미 있으므로 재제작하지 않는다. 유신의 실제 효과 이벤트가 오면 해당 VFX/SFX를 연결한다.

완료: 목업의 클릭 흐름이 실제 성장 API로 동작한다. UI 작업 씬·프리팹·코드와 두 해상도 화면을 전달한다.

## 태환 — 실제 빌드 QA

1. 전달받은 정확한 SHA/미커밋 상태와 Unity 6000.3.17f1, 실행 파일 해시를 기록한다.
2. 시작 원소 5종, 인접 원소 해금, 특화 누적, 정보 열람, 중복 확정, 다중 레벨업, 7→8 복귀, 전체 MAX와 재시작 초기화를 검사한다.
3. 각 원소 레벨 1·3·5·8의 실제 효과와 외형을 나눠 확인한다. 이미 발사된 탄 유지, 풀 재사용, 일시정지도 확인한다.
4. 정상 속도로 엘리트 3/6분 → 보스 8분 → 승리, 별도 사망·10분 시간 초과, 재시작·타이틀·프로그램 종료를 검사한다.
5. 두 해상도에서 UI·이동 중 바닥·마법 식별·적 가림을 확인한다. 같은 적/투사체 수로 적용 전후 성능을 비교한다.

완료: 재현 순서·예상/실제·화면·로그·성능 수치가 있는 PASS/FAIL/미검증 보고서. 가상 입력과 사람이 직접 조작한 결과를 구분한다.

## 전달 형식과 순서

- 선동이 성장 계약을 먼저 제공한다. 승범은 목업 UI, 유신은 기존 기획의 기본 전투 효과부터 작업할 수 있다.
- 각자 **커밋 SHA, 변경 경로, 공개 API, 작업 씬/프리팹, 검증 결과, 남은 결함**을 전달한다.
- 팀원은 자기 영역만 수정한다. 최종 통합 씬과 빌드는 선동이 만든다.
- 현재 간이 통합본의 완주는 최종 몬스터 패턴·특화 시스템 완성을 뜻하지 않는다.
